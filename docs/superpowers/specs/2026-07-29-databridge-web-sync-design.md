# DataBridge — MySQL 数据同步工具 Web GUI 设计文档

> 日期：2026-07-29
> 依据：[mysql-sync-requirements.md](../../../mysql-sync-requirements.md) + 需求方本轮澄清确认。
> 本文档为本迭代（Web GUI）的完整设计方案，已经需求方逐节确认。

## 1. 迭代范围调整（相对原需求文档）

原需求文档规划"同步引擎 + Web GUI + stdio MCP"为一个迭代。需求方本轮确认调整为：

- **本迭代只做 Web GUI**（含新功能"勾选行同步"），MCP stdio 入口顺延到下一迭代；
- 架构上仍必须保证：同步引擎与入口层（Web / 未来 MCP）完全解耦，MCP 接入时不改引擎。

本迭代交付三个页面功能：

1. **连接管理**：连接的增删改查、测试连接、受保护标记；
2. **数据浏览器 + 勾选行同步**（新功能）：双网格浏览源/目标表数据，勾选行执行"新增"或"替换"；
3. **整表增量同步**：按主键比对 → 预览行数 → upsert 执行（原需求 §3 语义不变）。

## 2. 总体架构与项目结构

分层原则：引擎层纯逻辑、无 Web 依赖；Web 层是薄壳；未来 MCP 层同样是薄壳。

```
DataBridge/
├── databridge/
│   ├── engine/              # 同步引擎（纯逻辑，不依赖 Web）
│   │   ├── connection.py    # MySQL 连接封装（pymysql）
│   │   ├── inspector.py     # 元数据：列结构、主键识别、列一致性校验
│   │   ├── browser.py       # 数据浏览：分页查询 + 列筛选 + 排序
│   │   ├── diff.py          # 整表增量比对（分批、主键逐行）
│   │   └── writer.py        # 写入：追加(去自增主键 INSERT)、N对N替换、upsert
│   ├── storage/
│   │   └── connections.py   # 连接配置存取（本地 JSON，密码 Fernet 加密）
│   └── web/
│       ├── app.py           # FastAPI 应用 + REST API
│       └── static/          # 单页前端（原生 JS + Tabulator，本地 vendor，无 Node 构建）
├── data/                    # 连接配置 + Fernet 密钥（整体 .gitignore）
├── tests/                   # pytest 单测（引擎层为主，mock 数据库）
├── mcp_server.py            # 【本迭代不做】后续 MCP 入口，直接调 engine
└── pyproject.toml           # uv 管理，Python 3.11+
```

技术栈：

| 项 | 选型 | 说明 |
|----|------|------|
| 后端 | FastAPI + Uvicorn | REST API + 静态文件托管 |
| 数据库驱动 | pymysql | 纯 Python，参数化查询 |
| 前端 | 原生 JS + Tabulator | 表格库自带复选框/筛选/排序/分页；静态文件 vendor 到本地，不依赖 CDN |
| 凭据加密 | cryptography (Fernet) | 密钥 `data/.key` 首次启动自动生成 |
| 包管理 | uv | 与 agent 项目一致 |

引擎层函数签名只接受「连接别名 + 库 + 表 + 参数」，由 storage 层解析别名取凭据；凭据不穿透到入口层。

## 3. 数据浏览器与勾选行同步（新功能核心）

### 3.1 页面布局与交互

- 页面上下两个数据网格：上为**源**、下为**目标**，各自独立选择「连接 / 库 / 表」；
- 每个网格：
  - 分页浏览，默认每页 50 行（可调），显示总行数；
  - 列头筛选：文本列支持 包含/等于，数值与日期列支持 等于/范围；点击列头排序；
  - 行首复选框，支持当页全选；勾选状态**跨页保留**（前端按主键记录勾选集合）；
  - 网格上方显示「已勾选 N 行」，可一键清空勾选。
- 后端查询为参数化 SQL；列名、排序方向经元数据白名单校验，防 SQL 注入。

### 3.2 操作一：新增到目标（追加）

- 把源网格勾选的 N 行追加插入目标表；
- 写入前**去掉自增主键列**，由目标表自增分配新 ID；
- 若源表主键不是自增：保留主键原样插入，主键冲突时报错回滚，**不静默覆盖**；
- 前置校验：两表列名集合必须**完全一致**（自增主键除外），不一致则拒绝并列出差异列。

### 3.3 操作二：替换目标勾选行

- 源勾 N 行、目标勾 M 行，要求 **N == M**，否则拒绝并提示两侧勾选数量；
- **按勾选顺序一一对应**：源第 1 个勾选 → 目标第 1 个勾选，依此类推；执行前弹出配对预览表供确认；
- 目标行**保留自己的主键**，其余列全部用对应源行的值 UPDATE 覆盖；
- 前置校验：列集合完全一致（同 3.2）。

### 3.4 执行流程（两操作共用）

1. 点击操作按钮 → 确认框展示摘要：操作类型、行数、目标连接/库/表、替换时的配对表；
2. 目标为**受保护连接**时，确认框额外要求勾选「我确认写入受保护库」，驱动 API 的 `confirm=true`；
3. 后端**单事务**执行全部行写入，任一行失败整体回滚；
4. 返回结果统计（成功 N 行 / 失败原因）；成功后目标网格自动刷新。

### 3.5 数据新鲜度

前端提交的是勾选行的**主键列表**而非整行数据；后端执行时按主键**从源库重新读取最新行**再写入，避免前端展示数据过期。替换操作对目标行同理按主键定位。

### 3.6 REST API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/browse` | 参数：连接别名、库、表、页码、页大小、筛选、排序；返回行数据+总数 |
| POST | `/api/rows/insert` | 源连接/库/表 + 勾选行主键列表 + `confirm`；追加到目标表 |
| POST | `/api/rows/replace` | 源勾选主键列表 + 目标勾选主键列表（按序配对）+ `confirm`；替换目标行 |

## 4. 整表增量同步

语义与原需求 §3 一致：

- 选择源/目标的连接/库/表，可填可选 WHERE 条件；
- **预览（dry-run）**：引擎按主键分批（每批 1000 行）比对，返回将新增行数、将覆盖行数、主键范围示例；不写任何数据；
- **执行**：分批 `INSERT ... ON DUPLICATE KEY UPDATE`，完成后展示统计（新增 N / 覆盖 N / 耗时）；
- 前置校验：目标表不存在，或两表主键结构不一致 → 报错并给出清晰提示，**不自动建表/改表**；
- 不做删除同步（源删目标存的行不处理）。

对应 API：`POST /api/sync/preview`、`POST /api/sync/execute`（后者受保护连接需 `confirm=true`）。

## 5. 连接管理

- 增删改查连接：别名、host、port、user、密码、可选默认库、「受保护」勾选框；
- 「测试连接」按钮：即时验证连通性；
- 列表与编辑页**永不回显密码**；编辑时密码留空表示不修改；
- 存储：`data/connections.json`，密码字段 Fernet 加密；密钥 `data/.key` 首次启动自动生成；`data/` 整体进 `.gitignore`；
- 配置文件不预置任何默认连接。

对应 API：`GET/POST/PUT/DELETE /api/connections`、`POST /api/connections/test`。

## 6. 安全护栏（server 侧实现）

1. 所有**写操作**（rows/insert、rows/replace、sync/execute）目标为受保护连接时，必须携带 `confirm=true`，否则返回 403 + 可读中文提示；GUI 用二次确认框驱动该参数；
2. **读操作**（browse、preview、connections 列表）不受限；
3. 任何 API 返回值、日志、异常信息不得包含密码；FastAPI 统一异常处理器兜底脱敏；
4. 凭据只存本地 `data/`，不进 git。

## 7. 错误处理

所有可预期错误返回结构化 `{code, message}`（中文 message），前端 toast 展示。覆盖场景：

- 连接失败 / 认证失败；
- 库或表不存在；
- 表无主键（勾选行同步与整表同步均要求有主键）；
- 列集合不一致（列出差异列）；
- 替换时两侧勾选数量不等；
- 受保护连接未携带确认参数；
- 主键冲突（非自增主键追加场景）。

## 8. 测试计划（pytest）

- `inspector`：列一致性校验（一致/不一致/差异列列举）、主键识别、无主键表报错、自增主键识别；
- `writer`：
  - 追加：去自增主键的 INSERT 语句生成；非自增主键保留；
  - 替换：N 对 N 配对、数量不等拒绝、UPDATE 语句生成（保留目标主键）；
  - upsert：`INSERT ... ON DUPLICATE KEY UPDATE` 语句生成；
  - 事务回滚（mock 连接验证 rollback 调用）；
- `diff`：分批比对逻辑，新增/变更行判定；
- 护栏：受保护连接写入未带 confirm 时拒绝；
- `storage`：密码加解密往返；持久化文件中无明文密码；
- Web 层：FastAPI TestClient 接口冒烟（含 403 护栏路径）。

数据库交互以 mock 为主；有本地 MySQL 时可补充集成测试（非门槛）。

## 9. 本迭代明确不做

- MCP stdio/HTTP 入口（下迭代，引擎已为其解耦）；
- 定时/自动触发同步；
- 删除同步；
- 表结构（DDL）同步 / 自动建表；
- 异构数据库（仅 MySQL → MySQL）；
- Docker 化（Dockerfile 可后补，不阻塞本迭代验收）。

## 10. 验收标准

1. 连接管理：能添加（含受保护标记）、编辑、删除、测试连接；密码不回显、不落明文；
2. 数据浏览器：双网格分别选择连接/库/表后可分页浏览、列筛选、排序、跨页勾选；
3. 勾选新增：源勾选 N 行 → 追加到目标表，自增主键由目标分配；列不一致时拒绝并列出差异列；
4. 勾选替换：源/目标各勾 N 行按序配对替换，目标主键保留；数量不等时拒绝；
5. 整表同步：预览返回新增/覆盖行数（不落数据），执行后数据正确落库并返回统计；
6. 护栏：目标为受保护连接且未确认时，三类写操作均被拒绝并返回可读提示；
7. 引擎核心逻辑单测全绿。
